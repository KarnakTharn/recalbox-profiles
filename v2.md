# 1. Ajout d'un system custom dans recalbox

## a. Copier du fichier systgemlist.xml
source : https://wiki.recalbox.com/fr/advanced-usage/systems-display  

L'ajout d'un système « custom » doit se faire uniquement à partir du fichier systemlist.xml présent dans le répertoire suivant `/recalbox/share/system/.emulationstation/systemlist.xml`
`.

D'origine, ce fichier n’existe pas. Il faut soit copier le fichier original, soit créer un nouveau fichier. Une fois le nouveau fichier créé, il est maintenant possible d'y ajouter un nouveau système.

emplacement du fichier d'original à copier : Ce fichier se situe dans le dossier `/recalbox/share_init/system/.emulationstation/systemlist.xml`.

```bash
cp -r /recalbox/share_init/system/.emulationstation/systemlist.xml /recalbox/share/system/.emulationstation
```
puis copier/coller les éléments du git présent dans /recalbox/share_init/system/.emulationstation/systemlist.xml`

## b. Modification du fichier
```xml
  <!-- Profiles - system custom -->
  <system uuid="21b8873a-a93e-409c-ad0c-8bb6d682bef8" name="profiles" fullname="Profiles">
    <descriptor path="%ROOT%/profiles_swap" theme="profiles_swap" extensions=".smc .sfc .mgd .zip .7z"/>
    <scraper screenscraper=""/>
    <properties type="console" pad="mandatory" keyboard="no" mouse="optional" lightgun="optional" releasedate="1990-11" retroachievements="1"/>
    <emulatorList>
      <emulator name="libretro">
        <core name="snes9x" priority="1" extensions=".bs .fig .gd3 .sfc .smc .swc .zip! .7z!" netplay="0" softpatching="1" compatibility="high" speed="high" crt.available="1" video.backend="default"/>
        <core name="mesen_s" priority="2" extensions=".bs .bsx .sfc .smc .zip! .7z!" netplay="0" softpatching="0" compatibility="high" speed="high" crt.available="0" video.backend="default"/>
        <core name="bsnes" priority="3" extensions=".bs .bsx .sfc .smc .zip! .7z!" netplay="0" softpatching="1" compatibility="high" speed="high" crt.available="1" video.backend="default"/>
        <core name="bsneshd" priority="4" extensions=".bs .bsx .sfc .smc .zip! .7z!" netplay="0" softpatching="0" compatibility="high" speed="high" crt.available="0" video.backend="default"/>
      </emulator>
    </emulatorList>
  </system>
  <!-- Profiles - system custom -->
```

Attention :
- Vérifier que l'UUID n'existe pas déjà dans le fichier `systemlist.xml`.
- Si besoin, modifier l'UUID pour qu'il soit unique.

# 2. ajout de ROMs fictives pour la sélection de profil

Dossier : `recalbox/share/roms/profiles_swap/`

Fichiers créés :
- `Guest.zip` — ROM fictive pour sélectionner le profil `Guest`
- `Profil1.zip` — ROM fictive pour sélectionner le profil `Profil1`

Ces fichiers sont des archives ZIP vides utilisées comme sélecteurs de profil. Comme ils sont vide, ES retourne une erreur, retour sur la sélection des jeux.

Autre option :
- Prendre des roms de snes
- Les renommer avec le nom des profils
- Ajuster le time.sleep dans la fonction kill_game du script de swap de profil.

# 3. script de swap de profil

Fichier : `recalbox/share/userscripts/swap_profile[rungame].py`

Événement : `rungame`

Fonctionnalités :
- Lit `/tmp/es_state.inf`
- Détecte le lancement d'une ROM du système `profiles`
- Extrait le nom du profil depuis le chemin du fichier ou le nom du jeu
- Vérifie l'existence du dossier du profil dans `/recalbox/share/profiles/`
- Met à jour `/recalbox/share/profiles/current_profile.json`
- Termine RetroArch avec un `SIGINT`
- Enregistre l'événement dans le fichier de log

Détails de fonctionnement :
- `SystemId` doit être `profiles`
- `GamePath` est utilisé en priorité pour retrouver le nom du profil
- Le profil doit exister sous `/recalbox/share/profiles/<profil>`
- Si le profil est valide, `current_profile.json` est écrit avec `{"profile": "<profil>"}`
- Le script cherche le PID de RetroArch via `pgrep retroarch`
- Après 10 secondes d'attente, RetroArch est terminé pour revenir à EmulationStation

Format du log :
```
[system] | [YYYY-MM-DD HH:MM:SS] | profiles | ProfileSwap | nom_du_profil
```

# 4. chargement et enregistrement des saves en fonction du profil

## 4.a. Chargement des saves au lancement d'un jeu

Fichiers :
- `recalbox/share/userscripts/load_saves[rungame].py`
- `recalbox/share/userscripts/load_saves[gamelistbrowsing].py`

Événements :
- `rungame` — utilisation classique pour le lancement d'un jeu
- `gamelistbrowsing` — utilisé si l'option "afficher les savestates avec le démarrage du jeu" est activée

Fonctionnalités communes :
- Lit `/tmp/es_state.inf`
- Ignore le système `profiles`
- Lit le profil courant depuis `/recalbox/share/profiles/current_profile.json`
- Extrait le nom du jeu depuis `GamePath`
- Cherche les fichiers de saves existants dans `/recalbox/share/profiles/<profil>/<system>/<game>.*`
- Copie ces fichiers vers `/recalbox/share/saves/<system>/`
- Supprime les saves globales si le profil ne contient aucune save pour le jeu
- Enregistre l'événement dans le fichier de log

Détails de fonctionnement :
- `SystemId` doit être différent de `profiles`
- La recherche des saves se fait par préfixe `game_name.`
- Les fichiers restaurés sont copiés dans le dossier de saves partagé
- `load_saves[gamelistbrowsing].py` s'utilise avec l'option de browsing pour afficher les save states au démarrage du jeu

Format du log :
```
[current_profile] | [YYYY-MM-DD HH:MM:SS] | <system> | GameStart | <game>
```

## 4.b. Enregistrement des saves à la fin d'un jeu

Fichier : `recalbox/share/userscripts/save_profile[endgame].py`

Événement : `endgame`

Fonctionnalités :
- Lit `/tmp/es_state.inf`
- Ignore le système `profiles`
- Lit le profil courant depuis `/recalbox/share/profiles/current_profile.json`
- Extrait le nom du jeu depuis `GamePath`
- Cherche les fichiers de saves modifiés dans `/recalbox/share/saves/<system>/<game>.*`
- Utilise un manifest `/recalbox/share/profiles/.sync_manifest.json` pour suivre les dates de synchronisation
- Copie uniquement les fichiers modifiés depuis la dernière synchro vers `/recalbox/share/profiles/<profil>/<system>/`
- Met à jour le manifest avec les nouveaux timestamps
- Enregistre l'événement dans le fichier de log

Détails de fonctionnement :
- Le manifest stocke une clé unique par fichier : `<profil>:<system>:<fichier>`
- Si aucun timestamp de synchro existe, le fichier est copié
- Après copie, le manifest est sauvegardé au format JSON

Format du log :
```
[current_profile] | [YYYY-MM-DD HH:MM:SS] | <system> | GameEnd | <game>
```

# 5. fichier de log

Fichier : `recalbox/share/profiles/profiles.log`

Format unifié des logs :
```
[system] | [YYYY-MM-DD HH:MM:SS] | profiles | ProfileSwap | nom_du_profil
[current_profile] | [YYYY-MM-DD HH:MM:SS] | snes | GameStart | Super Mario World
[current_profile] | [YYYY-MM-DD HH:MM:SS] | snes | GameEnd | Super Mario World
```

Contenu :
- **[system]** : Changements de profil enregistrés par `swap_profile[rungame].py`
- **[current_profile]** : Début et fin de parties enregistrés par `load_saves[rungame].py` et `save_profile[endgame].py`
- Le système `profiles` est automatiquement exclu des opérations de save/load

Notes :
- Le logging est intégré dans chaque script sans module externe
- Les événements sont ajoutés en append dans `profiles.log`

# 6. Thème

Le thème fonctionne maintenant pour Recalbox Next.

## a. Recalbox Next

- Le système `profiles` doit être déclaré dans `/recalbox/share/system/.emulationstation/systemlist.xml`
  avec un `descriptor` contenant `theme="profiles_swap"`.
- Recalbox Next utilisera alors le thème associé si le dossier de thème est présent.

## b. Fichiers de thème

- Vérifier que `recalbox/share/themes/recalbox-next/_views/_partials/systems/profiles.xml` existe.
- Si nécessaire, copier/coller le fichier de thème depuis une source Recalbox Next valide.
- S'assurer que les chemins et les assets du thème sont accessibles dans `recalbox/share/themes/recalbox-next/`.

## c. Comportement attendu

- Le système `profiles` doit s'afficher avec le thème Recalbox Next compatible.
- Les sélecteurs de profil (`Guest.zip`, `Profil1.zip`) s'affichent comme n'importe quel autre système.
- Si le thème ne s'affiche pas, vérifier que :
  - le `systemlist.xml` utilise bien `theme="profiles_swap"`
  - le dossier du thème existe dans `recalbox/share/themes/recalbox-next/`
  - le nom du système (`profiles`) correspond bien au nom du fichier de thème
    (`profiles.xml` dans `_views/_partials/systems/`)
