# 1 .ajout d'un system custom dans recalbox

## a
source : https://wiki.recalbox.com/fr/advanced-usage/systems-display
L'ajout d'un système « custom » doit se faire uniquement à partir du fichier systemlist.xml présent dans le répertoire suivant /recalbox/share/system/.emulationstation/systemlist.xml.

D'origine, ce fichier n’existe pas. Il faut soit copier le fichier original, soit créer un nouveau fichier. Une fois le nouveau fichier créé, il est maintenant possible d'y ajouter un nouveau système.

emplacement du fichier d'original à copier : Ce fichier se situe dans le dossier /recalbox/share_init/system/.emulationstation/systemlist.xml.

Fichiers créés : `recalbox/share/roms/profiles_swap/`

# 3. script sur event pour le swap de profil

Fichier : `recalbox/share/userscripts/swap_profile[rungame].py`

Événement : `rungame`

Fonctionnalités :
- Détecte quand une ROM du système "profiles" est lancée
- Extrait le nom du profil depuis le nom du fichier
- Vérifie que le profil existe dans `/recalbox/share/profiles/`
- Met à jour `current_profile.json` avec le nouveau profil
- Termine RetroArch
- Enregistre l'événement dans le fichier de log

Format du log : `[system] | [YYYY-MM-DD HH:MM:SS] | profiles | ProfileSwap | nom_du_profil`


# 4. chargement et enregistrement des saves en fonction du profil

## 4.a. Chargement des saves au lancement d'un jeu

Fichier : `recalbox/share/userscripts/load_saves[rungame].py`

Événement : `rungame`

Fonctionnalités :
- Récupère le profil courant depuis `current_profile.json`
- Récupère les infos du jeu depuis `/tmp/es_state.inf`
- Cherche les saves du jeu dans le dossier du profil (`/recalbox/share/profiles/<profil>/<system>/<game>.*`)
- Restaure les saves vers `/recalbox/share/saves/`
- Ignore le système "profiles"
- Enregistre l'événement dans le fichier de log

Format du log : `[current_profile] | [YYYY-MM-DD HH:MM:SS] | <system> | GameStart | <game>`


## 4.b. Enregistrement des saves à la fin d'un jeu

Fichier : `recalbox/share/userscripts/save_profile[endgame].py`

Événement : `endgame`

Fonctionnalités :
- Récupère le profil courant depuis `current_profile.json`
- Récupère les infos du jeu depuis `/tmp/es_state.inf`
- Cherche les saves modifiés dans `/recalbox/share/saves/`
- **Sauvegarde intelligente** : utilise un manifest (`.sync_manifest.json`) pour tracker les dates de modification
- Ne copie que les fichiers modifiés depuis la dernière synchro
- Copie les saves vers le dossier du profil (`/recalbox/share/profiles/<profil>/<system>/`)
- Ignore le système "profiles"
- Met à jour le manifest avec les nouveaux timestamps
- Enregistre l'événement dans le fichier de log

Format du log : `[current_profile] | [YYYY-MM-DD HH:MM:SS] | <system> | GameEnd | <game>`


# 5. fichier de log

Fichier : `/recalbox/share/profiles/profiles.log`

Format unifié des logs :
```
[system] | [YYYY-MM-DD HH:MM:SS] | profiles | ProfileSwap | nom_du_profil
[current_profile] | [YYYY-MM-DD HH:MM:SS] | snes | GameStart | Super Mario World
[current_profile] | [YYYY-MM-DD HH:MM:SS] | snes | GameEnd | Super Mario World
```

Contenu :
- **[system]** : Changements de profil (généré par `swap_profile[rungame].py`)
- **[current_profile]** : Lancements et fins de jeux (généré par `load_saves[rungame].py` et `save_profile[endgame].py`)
  - Exclut automatiquement le système "profiles"

Logging intégré dans chaque script (pas de module externe) pour éviter un lancement involontaire.
